# MSP Student FAQ

A search-first FAQ for Maastricht Science Programme students. Static, installable (PWA), works offline. Live: **https://msp-faqs.nl** (the old `msp-operations.github.io/MSP-FAQ-s/` and `beebzoo.github.io` URLs redirect here)

No frameworks, no build step, no dependencies, nothing loaded from another company's servers. Fonts, the search engine and the PDF reader are all vendored in `assets/vendor/`, deliberately, because this handles student data. Keep it that way.

---

## ✏️ Where the answers live (read this first)

**All the questions and answers live in one file: `content.json`.** That is the single source of truth the app reads. You do not edit the app code to change an answer.

`content.json` is generated from the master document
`MSP/_Inventory/Knowledge Base/MSP Student FAQ - MASTER.md`, which is organised by office (Board of Examiners, Exams, BTR, and so on).

### To change or add an answer
1. Edit the master document (`MSP Student FAQ - MASTER.md`) in the right office section.
2. Regenerate the app content:  `node tools/convert.mjs`
3. Rebuild the single-file offline copy:  `node tools/build-offline.mjs`
4. Commit and push. The live site rebuilds automatically in about a minute (push = deploy).

That is the whole loop. Do not edit `content.json` by hand: the next `convert.mjs` run overwrites it, so the change silently disappears and the master and the app drift apart.

## 👤 Who owns what (twice-a-year review)

Each office owns its own answers. The review packs (one Word doc per office, with their questions,
answers, and open "please confirm" flags) plus the ownership overview live in
`MSP/_Inventory/Knowledge Base/_FAQ Maintenance/`. Regenerate fresh before each review round:
`node build-review-docs.mjs` in that folder, then `powershell -File convert-to-docx.ps1` (needs a
normal desktop session for Word). Returned docs feed edits into the MASTER, never into the app directly.

## What each file is

| File | What it is | Do you edit it? |
|---|---|---|
| **`content.json`** | Every question, answer, topic and office. The source of truth. | Rarely (edit the master instead) |
| `index.html` | The whole app (search, cards, answer view). Renders `content.json`. | Only for features/design |
| `sw.js` | Service worker: offline cache. Bump `CACHE` only when the file list changes, not for content edits (see the comments in the file). | Only when files change |
| `content.staff.json` | The internal `[NEEDS MARTIJN]` notes, generated alongside `content.json`. Gitignored, never deployed. | No |
| `manifest.webmanifest` · `icon.svg` · `assets/` | PWA manifest, icon, logos and the building photo. | Rarely |
| `tools/convert.mjs` | Turns the master document into `content.json`. Holds the office list with their mailboxes, and the office → topic mapping. | When adding an office/topic |
| `degree-data.json` | Course catalogue used by the degree check. Generated by the Degree-Checker project. | Never by hand |
| `MSP-FAQ-offline.html` | The whole app in one self-contained file (for Canvas/USB/email). Opens offline from a double-click; when online it fetches the newest answers from the live site by itself. No transcript feature. | Never by hand (regenerate with `tools/build-offline.mjs`) |
| `tools/serve.mjs` | Local preview: `node tools/serve.mjs` → http://localhost:8099 | No |

## 🧭 Finding your way around `index.html`

The whole app is one file: markup, styles and script. Both halves are split into
numbered, banner-commented regions, so search for the banner rather than scrolling.
The comments in the file are the real documentation; this is just the index.

**Stylesheet** (top of the file, inside `<style>`)

| I want to change | Go to |
|---|---|
| a colour, corner radius or font used everywhere | region 1, design tokens |
| the dark-mode palette | region 1, the `html.dark` block |
| the keyboard focus ring | region 2 |
| the logo or the two floating masthead buttons | region 3 |
| the hero photo or the blue wash over it | region 4, `.hero` |
| the search box and its dropdown | region 5 |
| the topic cards on the home page | region 6 |
| how an answer looks, open or closed | region 7 |

**Script** (bottom of the file, inside `<script>`)

| I want to change | Go to |
|---|---|
| dark-mode behaviour | region 2 |
| a topic's colour | region 3, the `C` and `CT` maps |
| a topic's icon | region 4, the `P` map |
| the shortcut chips under the search box | region 5, `CHIPS` |
| the search synonyms (sick → attendance) | region 5, `SYN` |
| search tuning (weights, fuzziness) | region 6, the MiniSearch options in `load()` |
| the blue quick-link tiles | region 6, `QUICK` |
| the URLs the app answers to | region 7, routing |
| what an answer row contains | region 8, `qHtml()` |
| anything about the transcript or degree check | regions 9 and 10, **and read the warning there first** |

**Adding a new topic** takes four edits: add it to `TOPICS` in `tools/convert.mjs`
(that is what puts questions in it), then to `C`, `CT` and `P` in `index.html` for
its colour pair and icon. Miss one of the three maps and the card still works, it
just falls back to blue with a question-mark icon.

**Adding an office** is one edit: a row in `OFFICES` in `tools/convert.mjs`, with
the header text to match in the master, a short key, the display name and the
mailbox. Give it a topic in `OFFICE_TOPIC` in the same file. Nothing in
`index.html` needs to change; an office with an empty mailbox simply gets no
"email this office" button.

## Notes
- **Staff / editor view:** add `?staff` to the URL to see the open `[NEEDS MARTIJN]` review flags inline, plus a "flags remaining" panel. It only works locally: the notes live in `content.staff.json`, which is gitignored and never reaches the live site.
- **The offline copy** is a build of the same `index.html` with the fonts, search engine, images and answers inlined, the service worker and transcript feature removed, and a "check for new answers" button added. `tools/build-offline.mjs` does this by finding exact snippets of `index.html` and swapping them, so **it fails loudly if you edit one of those snippets**. That is on purpose. Always run it after touching `index.html`; if it says "Anchor not found", update the matching string in that script.
- Deploy: push to `main` → GitHub Pages rebuilds.
